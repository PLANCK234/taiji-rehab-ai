# ADR-0015 — 工作人员端与患者端分开建设

2026-11-05；状态：产品方向由用户确认，工程实现与临床/机构准入尚未批准。

## 背景与选择

现有系统只有工作人员账号、研究与编号对象范围授权及合成数据演示。原 PRD 将患者端排除；用户现要求同一平台也供患者使用，并明确第一版患者功能为查看医护确认的计划/视频、记录训练与不适。可选方案是直接扩充当前工作台，或建设共享后端但权限和页面独立的患者入口。

## 决定

采用独立患者入口、独立患者角色与“只能访问本人”服务端授权；工作人员入口继续负责评估、审批、科研记录和查看患者反馈。患者端第一版仅显示医护明确确认、发布给该患者且仍有效的计划及经审核视频，并允许记录训练事实与不适。患者不在第一版自行填写评估量表，也不能直接收到 `DEMO_RULE`、模型候选或未发布的训练建议。缺失反馈保持未知；不适报告不能被页面自动判定安全或替代机构处置。

## 后果与验收边界

开发先用合成账号/编号对象，不开放真实身份或真实健康数据。必须新增账号与本人绑定/撤销、最小权限、计划发布/撤回与版本、视频审核来源、训练/不适记录及工作人员查看的审计与测试。真实患者上线仍取决于 Q-01/03/04/07/08/09/14/15 等批准，不能因页面完成或临时外链可访问而视为获准。当前代码没有患者角色或患者页面，也没有经医护发布的计划或视频，因此本 ADR 不宣称功能已完成。

## 复核触发与批准

患者端需求、研究方案、临床内容或机构部署条件改变时复核。产品方向来自用户本次选择；临床内容、真实数据与机构上线仍须相应授权负责人签核。
