# ADR-0018：减少操作摩擦、动作库内容与 pose-geometry-v3

状态：已实施（2026-11-26，分支 `feat/ux-refresh`）

## 背景

早期实现为了防止误用，加入了一些对目标帮助不大、却明显增加使用门槛的限制：更正原因必须写成 `SYN-CORRECTION` 这样的代码；建档表单里勾选“模拟同意”却不会真正记录同意（除非再勾选另一个开关）；12 个太极动作的内容全是“观看示意 / 记录演示动作”；AI 只给出关节角度，看不到太极最关键的立身中正、重心转移；页面上处处重复免责声明。

## 决定

1. **更正原因改为自由文本**（≤240 字，去首尾空白，空白视为未填）。CSV 导出本来就不含该列（ADR-0013），因此不扩大数据外流面。迁移 `0011` 把 `assessment_revisions.change_reason` 从 64 放宽到 240。
2. **一张建档表单，三种结果**：只填编号 → 建档；勾选同意 → 同时写入模拟同意；再填 SPPB → 一步完成评估、确认与 Demo 分级。同意仍须**明确勾选**，绝不默认。
3. **动作库写入真实要领**：依据通用简化太极拳技术写出动作说明与 4 步要领，不含剂量、强度或疗效声明。种子脚本拥有这些 `DEMO_ONLY` 行，再次运行时更新文本；运行记录引用稳定的动作 ID，不受影响。非 `DEMO_ONLY` 行仍拒绝改动。
4. **pose-geometry-v3**（迁移 `0011` 放开版本约束；v1/v2 记录原样保留）：
   - 躯干偏离竖直角（肩中点–髋中点连线与图像竖直方向夹角，中位数与 P5–P95 波动，含平滑/噪声估计）；
   - 骨盆中心左右 / 上下移动幅度，以中位躯干长度归一化（%），对拍摄距离不敏感；
   - 肘/肩/膝左右平滑幅度差。
   这些都是图像平面描述量，不推断 SPPB、康复阶段或动作合格与否；关键点不足时为 `null` 并给出原因。
5. **界面**：新中式设计系统（见 [设计系统](../product/DESIGN_SYSTEM.md)），流程进度条 + “下一步”卡片；Demo 标识集中到顶部横幅；中止训练改为页面内两步确认（小程序没有原生 `confirm`）。
6. 移除被 AI 页取代的 SVG“姿态拍照演示壳”及其仅依赖模拟 API 的浏览器测试。

## 不变的边界

服务器端 RBAC/对象范围、CSRF、幂等键、追加式历史、模拟同意门禁、Research 配置拒绝、`DEMO_ONLY` 标记、零分/缺失/无效区分——全部保留。

## 后果

- 回退 `0011` 时若已有 v3 记录或超过 64 字的更正原因会被拒绝，避免截断数据。
- 真实浏览器测试同步更新：建档勾选同意即记录同意；中止训练需“确认中止”。
