# DEMO-V2-16A：合成视频核对与患者播放契约

状态：2026-11-10 工程设计；**没有视频素材、审核记录或已实现的播放接口**。本契约只约束下一项合成演示实现，不批准临床视频、真实患者使用或影像采集。

## 素材准入

- 只接受项目自行制作的非指导性流程演示短片，或另有可核验授权的合成素材。不得包含真实患者影像、太极动作教学、训练剂量、适应证、疗效或安全结论。
- 素材入库前记录来源、制作/授权人、用途范围、文件格式、时长、字节数与 SHA-256；审核者实际观看文件，并确认画面与声音均符合“仅用于流程测试”。没有素材时保持 `awaiting_review`，不得创建通过记录。
- 第一版只允许随仓库版本发布的固定本地素材清单；拒绝客户端提交视频 URL、任意路径、文件上传或从第三方站点热链。正式素材存储、权利及保留策略另由 Q-15、Q-10 决定。

## 合成流程状态与责任

1. 素材登记后为 `pending_review`；已分配该合成对象的医护在工作台查看素材来源、摘要和完整预览，并明确勾选“仅为合成流程核对，不是临床审核”。
2. 服务端追加核对事件，记录素材标识、内容哈希、核对结果、操作者和时间。只有 `reviewed_for_demo` 且文件哈希仍匹配的素材可供合成卡片选择。拒绝或文件变化必须重新核对；旧事件不得改写。
3. 发布请求只接受固定卡片代码及已核对素材标识、期望发布版本和现有 Demo 确认。服务端再次检查医护角色与对象分配、活跃患者绑定、当前模拟同意、素材哈希及核对结果、CSRF 和幂等键；发布事件保存素材标识及哈希快照。仍允许不带视频的现有卡片发布，显示待添加。
4. 患者播放请求每次验证当前登录患者的本人绑定、模拟同意和最新有效发布事件，以及该事件的素材快照仍可用；撤回、绑定撤销、同意失效、文件哈希不符或版本替换后拒绝旧视频读取。响应禁止共享缓存，并支持浏览器播放所需的分段读取。不能仅凭静态 URL 绕过这些检查。
5. 患者页面同时显示“合成流程测试视频，不是训练指导”、素材状态与当前发布版本。工作人员可看到发布及核对历史，但不能把核对标为临床确认。

## 下一实现的验收

- 有符合准入条件的真实文件、可核验来源/授权与 SHA-256，并由人实际观看后，才允许记录 `reviewed_for_demo`；无文件、未核对、哈希变化和拒绝状态均不能播放。
- 一次性 PostgreSQL 中核对事件和发布版本追加保存；刷新仍可见历史，旧发布行保持待添加。错误角色、跨对象、未绑定、模拟同意撤销、陈旧版本、缺 CSRF 或重复请求均按既有权限/幂等规则处理。
- 实际 Chromium 验证患者本人能播放当前已核对素材；其他患者、未登录、撤回后及旧版本 URL 均拒绝。核对响应无共享缓存，不泄露任意文件路径或真实身份。
- 前后端测试、迁移、数据库到浏览器验收和临时资源清理通过后，才可把合成播放子集记为完成。AT-PAT-02 的正式临床标准仍待 Q-03/Q-09/Q-15 及机构审批。

## 当前停止点

仓库没有 `.mp4`、`.webm` 等素材；本机没有可用的视频制作工具，现有隔离测试镜像也没有可启动的 Chromium。当前代码的 `video_status=awaiting_review` 和患者“视频待添加”是准确状态。取得合规合成文件后实现本契约；不能用假“已审核”状态或没有视频的播放器冒充验收。
