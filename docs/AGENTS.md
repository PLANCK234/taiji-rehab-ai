# Documentation agent instructions
- `docs/product/PRD.md` is the software scope baseline; `docs/OPEN_QUESTIONS.md` contains unresolved approvals.
- Do not replace source-stated facts with assumptions. Label proposals, decisions and research protocol dependencies.
- Keep requirement IDs stable; update traceability and acceptance tests when behavior changes.
- Architecture changes require an ADR. Never claim unperformed tests or completed clinical approval.
- Prefer concise, linked Markdown and executable examples over duplicate descriptions.
